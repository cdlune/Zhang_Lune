# 拆解：一套"LLM 驱动的 A 股短线全自动交易驾驶舱"是怎么做出来的

> 基于三张截图的逆向分析（"小王量化 · 全自动量化交易驾驶舱 · intel_short_v1"），以及本仓库的复刻实现说明。

## 1. 从截图读出的系统边界

| 截图里的元素 | 说明它背后有什么 |
| --- | --- |
| `实盘 · live-main`、`实盘写已启用`、`本地台账 / 柜台视图` | 有**本地账本**和**券商柜台**两套数据，区分"读"和"写"两种权限，并且会定期对账 |
| 执行链路 6 张卡：五源情报采集 → 两级选票漏斗 → 交易意向发布 → 区间执行器 → T+3 强制复评 → 预算与风控台账 | 一条**按时点调度**的流水线（00:00-09:15 / 09:15 / 盘前+滚动 / 09:30-14:55 / T+3 / 全天） |
| "大模型实时盘中推演（第 15 轮 · 10 分钟滚动节拍）" | 盘中定时（10/15 分钟）把盘面快照喂给 LLM，LLM 输出**结构化 JSON** |
| 宏观研判里的 `strong_bullish`、`panic_bearish`、`is_extreme_panic=true`、`review_set 为空`、`price_vs_vwap` | LLM 的输入是程序算好的特征（JSON 字段名漏到了自然语言输出里）——**数值都是代码算的，LLM 只做判断和写理由** |
| 【大盘极端弱势防守铁律】上涨比例 <25%、+3.5% 黄金低吸上限、偏离 VWAP、行业排名 85/110 非主线、成交额不足 5000 万、茅台一手 14 万超单笔预算 | 一组**硬规则**。成熟的做法是写在代码里先过滤，提示词里再写一遍让 LLM 给出一致的归因 |
| 活动意向表：标的 / 动作 / 状态 / 价格区间 / 目标量 / 配额 / 档位 / 置信度 / 到期 14:50 / 理由 | LLM 不直接下单，而是发布**"意向"**；由区间执行器在价格落入区间时才报单 |
| 风控中枢：单日买入上限 35000、单笔 10000、总仓位 95% / 单票 25%、5 席位、单笔 2000 股、10 笔/日、撤单 10 笔 | 一个与 LLM 无关的**前置风控引擎**，参数有版本号 `cfg-9b24f10e…` |
| 暂停调度 / 一键清仓 / 只读防误触 / 人工干预 / 事件流（风控·委托·对账·审计） | 运维层：熔断开关、审计日志、人工兜底 |
| 雷达图：事件冲击 / 信息新颖 / 资金流向 / 技术动能 / 安全边际 / 合规风控 / 模型置信，对比"全池基准" | 漏斗第二级给每只候选算的**多因子分数** |

## 2. 核心设计思想

1. **LLM 是"交易员"，不是"交易系统"。** 它只负责把多源信息综合成判断和理由；数据计算、风控、下单、对账都是确定性代码。
2. **意向 ≠ 委托。** LLM 每轮给出 `{标的, 方向, 价格区间, 数量, 置信度, 到期}`，执行器按行情逐 tick 判断是否触发。好处是：LLM 调用频率低（10-15 分钟一次，成本可控），执行仍然是毫秒级规则。
3. **铁律双保险。** 规则先在代码里过滤候选（LLM 根本看不到不合格的买点），LLM 输出后再做一次后置校验（越界的意向直接丢弃），最后报单前风控引擎再检查一次。
4. **宁缺毋滥是默认值。** 截图中大量轮次都是"风控未开仓"，这正是系统设计的目标：大多数时间不交易。
5. **双账本对账。** 本地台账与券商柜台不一致时立即熔断，阻止新开仓。

## 3. 复刻实现的模块对照

```
quant_cockpit/
├── backend/
│   ├── config.py   Settings + RiskConfig（参数哈希出版本号 cfg-xxxx）
│   ├── clock.py    北京时间交易时钟 / 可加速模拟时钟 / 交易阶段 / 交易日计算
│   ├── market.py   MarketProvider 接口；SimMarket（可复现的模拟盘）；AkShareMarket（东方财富全市场快照）
│   ├── intel.py    ① 五源情报：公告/新闻快讯/资金流/龙虎榜/政策研报
│   ├── llm.py      OpenAI 兼容（DeepSeek/Qwen/Kimi）、Anthropic、Mock；日预算记账；超预算/失败自动降级
│   ├── risk.py     ⑥ 前置风控：金额、数量、仓位、席位、时间窗、涨跌停、只读、熔断
│   ├── broker.py   PaperBroker（A 股 T+1、100 股整手、涨跌停撮合、佣金/印花税/过户费）；QmtBroker（miniQMT 骨架）
│   ├── engine.py   ②漏斗 ③推演+意向 ④区间执行 ⑤T+3复评/止损 + 对账 + 一键清仓 + 视图聚合
│   └── app.py      FastAPI：后台 tick 循环 + /api/state + /api/control + /api/risk
├── frontend/       无依赖单页：执行链路、风控中枢、持仓/委托/成交、事件流、LLM 推演、意向表、因子雷达、情报
└── tests/          风控、撮合 T+1、防守铁律、多日端到端
```

### 一次滚动推演的数据流

```
行情快照 ──► 宽度统计(上涨比例/涨跌停/情绪标签) ──► guard_candidates()  ← 代码铁律
                                                    │ 合格候选 / 被拒候选+原因
持仓 + T+3 标记 ──────────────────────────────────────┤
预算(现金/日买入余额/席位) ─────────────────────────────┤
                                                    ▼
                                    LLM（JSON：macro / rejections / holdings_review / intents）
                                                    ▼
                                validate_intents()  ← 后置校验，越界丢弃/修正
                                                    ▼
                                intents 表（已发布）──► 区间执行器(每 tick) ──► RiskEngine.check ──► Broker
                                                                                              ▼
                                                                    成交回报 → 本地台账 → 对账 → 熔断
```

## 4. 走向实盘需要补的部分

| 模块 | 本仓库 | 实盘建议 |
| --- | --- | --- |
| 行情 | AkShare 30 秒快照 | 券商 Level-1/Level-2 推送（QMT `xtdata.subscribe_quote`）、Tushare Pro |
| 情报 | 模拟 + 财联社电报 + 资金流 | 巨潮公告、交易所互动易、研报库、新闻 API；LLM 做情感/新颖度打分并缓存 |
| 柜台 | PaperBroker / QmtBroker 骨架 | miniQMT / PTrade / 券商 API；需要券商开通程序化交易权限，并按交易所要求做程序化交易报备 |
| 交易日历 | 只跳过周末 | 接入交易所节假日日历 |
| 调度 | 单进程 asyncio | 加进程守护、断线重连、启动时从柜台恢复状态 |
| 回测 | 无 | 先用历史分钟线回放 SimMarket 接口验证规则，再纸面交易至少 1 个月 |

## 5. 风险提示

LLM 的输出有随机性，会编造理由，也可能被情报里的文字影响（提示词注入）。所以本设计把所有资金相关的约束都放在代码里，LLM 只能在约束范围内做选择。即便如此，这套东西仍然是实验性系统：实盘前请用模拟和纸面交易充分验证，资金规模从小做起，并遵守券商和交易所的程序化交易监管要求。
